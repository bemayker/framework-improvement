## Potential conflicts with other independent features
Per `.claude/feature_map.md`, both TEST-02 (Health endpoint) and TEST-03 (Simple note form) declare `depends_on: [TEST-01]`. Neither is independent of TEST-01 and neither can run concurrently with it: the scaffold gate blocks both until TEST-01 is Done. So there is **no concurrency conflict against TEST-01 itself**.

The relevant downstream risk, recorded here for the scheduler once TEST-01 merges:
- `backend/app/main.py` (the FastAPI app entry): flagged in `feature_map.md` shared_risk_notes as touched by **both TEST-02 and TEST-03** for router registration. TEST-01 creates this file as a bare skeleton; TEST-02 and TEST-03 each register a router on it. TEST-02 and TEST-03 become ready simultaneously once TEST-01 is Done and are otherwise independent, so they must be **serialized** (not run concurrently) to avoid a merge conflict on `backend/app/main.py`. This is not a conflict for TEST-01, but TEST-01's skeleton should keep the app-entry structure minimal and stable to make that later serialization clean (a single clear place to register routers).
