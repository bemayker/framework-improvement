## Plan Overview
Backend-only extension of the existing `GET /api/version` endpoint (TEST-05). The commit value has one declared source: the `BUILD_COMMIT` environment variable, read in the existing settings module `backend/app/core/config.py` next to `DATABASE_URL` and `CORS_ORIGINS` (per `coding_standards.md` Section 5's invariant: within one settings module every deployment-dependent value reads the environment the same way, with a documented default). It is baked into the backend image at build time through a Dockerfile `ARG`/`ENV` pair and a compose build arg. The service layer (`version_service.py`) resolves it: blank becomes `"unknown"`, longer than 12 characters is cut to the first 12. The `VersionResponse` Pydantic schema gains a `commit: str` field, and the router fills it from the service. No database, no new dependency, no new router, no frontend change.

## Backend Plan
- Endpoints: `GET /api/version` (existing, `backend/app/routers/version.py`): response gains `commit`. Router stays a thin pass-through: `VersionResponse(version=get_app_version(), commit=get_build_commit())`. No literal commit string in the router.
- Configuration: `backend/app/core/config.py` → `Settings` gains `build_commit: str | None = field(default_factory=lambda: os.environ.get("BUILD_COMMIT"))`, read per call like `database_url` (so tests can `monkeypatch.setenv` against the session-scoped client). The raw value is stored; resolution lives in the service.
- Service layer: `backend/app/services/version_service.py` gains `UNKNOWN_COMMIT = "unknown"`, `COMMIT_LENGTH = 12` and `get_build_commit() -> str`, which reads `get_settings().build_commit`, strips whitespace, returns `UNKNOWN_COMMIT` when the result is empty or `None`, and otherwise returns `value[:COMMIT_LENGTH]`. Called per request, never cached at import.
- Schema: `backend/app/schemas/version.py` → `VersionResponse` gains `commit: str` (required field, docstring updated).
- Build-time wiring: `backend/Dockerfile` declares `ARG BUILD_COMMIT` (no default) and `ENV BUILD_COMMIT=$BUILD_COMMIT`, placed after the dependency-sync layers so a new sha does not invalidate the uv cache layer. `docker-compose.yml` → `backend.build` gains `args: BUILD_COMMIT: ${BUILD_COMMIT:-}` so `BUILD_COMMIT=<sha> docker compose build backend` or a `.env` entry reaches the image. The `"unknown"` default is owned by the service alone (one value, one source, `coding_standards.md` Section 5); Dockerfile and compose pass through an empty value rather than restating the default.
- `.env.example`: add a commented, optional `BUILD_COMMIT=` entry with a one-line explanation (README already references "optional BUILD_COMMIT" in `.env.example`, which currently does not hold it).
- Repository layer: none (no data access).
- Migrations: none.

## API Contract
- Method: GET
- URL: `/api/version`
- Request: no body, no query parameters.
- Response: 200, `application/json`, schema `VersionResponse`:

```json
{"version": "0.1.0", "commit": "3f9c2a71b0de"}
```

  With `BUILD_COMMIT` unset or blank: `{"version": "0.1.0", "commit": "unknown"}`. With `BUILD_COMMIT=3f9c2a71b0de4c5e8a9f00112233445566778899` (40 chars): `"commit": "3f9c2a71b0de"`. With `BUILD_COMMIT=abc1234`: `"commit": "abc1234"`.
- `POST /api/version` remains 405 (unchanged).

## Technology Selection
- Reading `BUILD_COMMIT`: chose the standard library `os.environ.get` inside the existing `Settings` dataclass over adding `pydantic-settings` or a new config module, because the project's settings module already reads every other environment value that way and stdlib covers it.
- Truncation to 12 characters: chose a plain string slice over any git library or subprocess call to `git rev-parse --short`, because the value arrives as an environment string at runtime and the container has no `.git` to query.
- Build-time injection: chose Docker's native `ARG`/`ENV` and the compose `build.args` key over a generated version file written during the build, because the native mechanism covers it with two lines and no extra artifact.
- No new dependency is added, so no lockfile changes.

## Manual verification plan
No criterion has a UI: the feature is a JSON endpoint. Each block below uses a terminal and the observable HTTP response instead of a click path.

### Criterion 1: `GET /api/version` returns 200 with `{"version": "<string>", "commit": "<string>"}`
Prerequisites: repository root checked out on the feature branch, Docker running, `.env` copied from `.env.example`.
1. In a terminal at the repository root run `docker compose up -d --build backend db` → both containers report started.
2. Run `curl -i http://localhost:8010/api/version` → status line `HTTP/1.1 200 OK`, header `content-type: application/json`, body is a JSON object with exactly two keys, `version` (for example `"0.1.0"`) and `commit`, both strings.

### Criterion 2: `commit` comes from `BUILD_COMMIT`, default `"unknown"`, first 12 characters when longer
Prerequisites: as Criterion 1.
1. Run `BUILD_COMMIT=3f9c2a71b0de4c5e8a9f00112233445566778899 docker compose build backend` then `docker compose up -d backend` → build completes, backend restarts.
2. Run `curl -s http://localhost:8010/api/version` → body contains `"commit":"3f9c2a71b0de"` (exactly the first 12 characters of the sha).
3. Run `BUILD_COMMIT=abc1234 docker compose build backend` then `docker compose up -d backend`, then `curl -s http://localhost:8010/api/version` → body contains `"commit":"abc1234"` (unchanged, not padded).
4. Open `backend/app/routers/version.py` → no commit literal appears in it; the value comes from `get_build_commit()`.

### Criterion 3: The response body is defined by a Pydantic schema in `backend/app/schemas/`
Prerequisites: backend running as in Criterion 1.
1. Run `curl -s http://localhost:8010/openapi.json` and find `components.schemas.VersionResponse` → `properties` lists `version` and `commit`, both `"type": "string"`, and `required` lists both.
2. Open `backend/app/schemas/version.py` → class `VersionResponse(BaseModel)` declares `version: str` and `commit: str`.

### Criterion 4: Unit and integration tests cover the set and unset commit paths
Prerequisites: `uv` installed; no database is needed for these files.
1. Run `uv run --directory backend pytest -q tests/unit/test_version_service_unit.py tests/unit/test_config_unit.py tests/unit/test_version_schema_unit.py tests/integration/test_version_integration.py` → summary line shows `0 failed`.
2. Run `docker compose build backend` with `BUILD_COMMIT` unset in the shell and absent from `.env`, then `docker compose up -d backend`, then `curl -s http://localhost:8010/api/version` → body contains `"commit":"unknown"`.
